はい。これが一通りできると、出来上がるのは単なる「社内文書チャット」ではなく、かなり実用寄りの **製造業向け・現場ナレッジAI SaaS** です。

一言でいうと、こういうシステムになります。

```text
製造現場のマニュアル、作業標準書、品質記録、点検表、トラブル報告、Excel台帳、図面、議事録などを取り込み、
現場担当者・保全担当・品質保証・若手技術者が、
根拠付きで質問・調査・報告書作成・チェックリスト作成・ナレッジ改善をできるAIシステム。
```

しかも、回答には必ず根拠が付き、危ない質問では承認済み文書がない限り断定しない、AI生成物は必ずドラフト扱い、という安全設計になります。

# 出来上がるシステムの全体像

構成としては、大きく3層です。

```text
001: 汎用RAG基盤
  文書取り込み、検索、回答、引用、ACL、テナント分離、評価、監査、コスト管理

002: 製造業向け業務レイヤー
  設備保全、品質不良、作業手順、技術継承、承認済み文書制御、ドラフト生成、KPI

Product/Governance レイヤー
  no-train、監査ログ、PoCダッシュボード、ガバナンス説明、ISMAP readiness
```

つまり、最終的には **「RAGエンジン」＋「製造業向け業務アプリ」＋「BtoB販売に必要なガバナンス」** を持ったシステムになります。

# 1. 文書・データを取り込む機能

製造業の現場で実際に使われるファイルを取り込めます。

| 対応データ                  | できること                             |
| ---------------------- | --------------------------------- |
| PDF                    | 設備マニュアル、作業標準書、検査基準、図面資料を取り込み      |
| DOCX / Word            | 手順書、報告書、教育資料を取り込み                 |
| XLSX / Excel           | 点検表、品質台帳、不良一覧、設備台帳を取り込み           |
| CSV                    | 台帳やエクスポートデータを取り込み                 |
| 画像 / スキャンPDF           | 図表、スクショ、ページ画像、スキャン文書をOCR・画像RAGで扱う |
| Markdown / HTML / text | 既存のナレッジ文書を取り込み                    |

特に製造業向けとして重要なのは、**Excelをセル範囲付きで引用できる**ところです。

たとえば回答の根拠として、

```text
不良履歴.xlsx
シート: 寸法不良一覧
セル範囲: B12:H18
```

のように返せる設計になります。

# 3. 根拠付きQ&A

現場ユーザーが自然言語で質問すると、AIが回答します。

ただし、普通のチャットボットと違って、回答には必ず根拠が付きます。

```text
質問:
E-142 が出た時、最初に何を確認すればいい？

回答:
E-142 は温度センサー異常に関連するアラームです。
まず、センサー配線の緩み、コネクタの接触、制御盤側の入力状態を確認してください。

根拠:
- 設備マニュアル p.42「E-142 温度センサー異常」
- 過去トラブル報告 TR-2024-017
- 月次点検表 シート「温度系統」 C12:F18
```

このシステムは、**根拠が弱い場合は答えません。**

```text
この質問に対して、承認済み文書から十分な根拠を確認できませんでした。
関連しそうな文書はありますが、正式な作業手順として断定できません。
```

これが現場利用ではかなり重要です。

# 4. 類似トラブル検索

設備保全や品質保証向けに、過去の類似事例を探せます。

たとえば、

```text
この異音トラブルに似た過去事例はある？
```

```text
この寸法不良の原因と対策で、過去に近いものを探して
```

と聞くと、

| 類似事例        | 原因     | 暫定対策 | 恒久対策   | 根拠   |
| ----------- | ------ | ---- | ------ | ---- |
| TR-2024-017 | 治具摩耗   | 治具交換 | 点検周期短縮 | 報告書  |
| TR-2023-082 | センサーずれ | 再調整  | 取付治具変更 | 品質報告 |
| TR-2022-055 | 温度条件ずれ | 条件補正 | 管理基準改定 | 議事録  |

のように返せます。

ポイントは、過去事例は **正式手順ではなく「参考・候補」として扱う** ことです。

```text
以下は過去事例に基づく候補です。
正式な作業手順として実施する前に、承認済み手順書と現場責任者の確認が必要です。
```

# 5. 安全ゲート

製造業向けとして一番大事な部分です。

このシステムは、危険作業や品質判断に関わる質問を検知します。

たとえば以下は high-risk query 扱いです。

```text
この設備を止めてもいい？
```

```text
安全カバーを外して作業していい？
```

```text
この不良品は出荷しても問題ない？
```

```text
この薬品の洗浄条件を変更していい？
```

high-risk と判定された場合、システムは安全側に倒します。

| ルール                 | 内容                           |
| ------------------- | ---------------------------- |
| 承認済み文書必須            | approved かつ有効な文書の引用がないと断定しない |
| draft / obsolete 禁止 | 古い文書や下書きを正式根拠にしない            |
| 過去事例は候補扱い           | 「参考」「候補」「過去事例」と明示            |
| 根拠不足なら拒否            | 推測で作業指示しない                   |
| 人間確認を促す             | 現場責任者・有資格者の確認を促す             |

つまり、売り文句としては、

```text
危険作業や品質判断について、AIが勝手に断定しない現場ナレッジAI
```

になります。

---

# 6. 承認済み文書・最新版・旧版の区別

製造業では、古い手順書を根拠にしてしまうと危険です。

このシステムでは、文書に以下の状態を持たせます。

```text
draft
pending_review
approved
obsolete
```

さらに、

```text
approved_by
approved_at
effective_date
obsolete_at
superseded_by
approval_source
```

を持ちます。

そのため、回答時にこう判断できます。

```text
この文書は approved か？
有効日内か？
obsolete ではないか？
外部QMS/DMS由来の承認情報か？
```

obsolete 文書を参照した場合は、警告を出します。

```text
注意: この文書は obsolete です。正式な作業根拠としては使用できません。
```

また、外部の QMS、DMS、SharePoint、Box、PLM に承認情報がある場合は、それを取り込める設計になります。

# 7. 報告書・チェックリスト・教育資料のドラフト生成

ここが「ただの検索AI」から「業務アシスタント」に進化する部分です。

ユーザーは、AIにドラフトを作らせられます。

| ドラフト種類    | 例                    |
| --------- | -------------------- |
| 点検チェックリスト | 月次点検表、始業前点検、異常時確認リスト |
| トラブル報告書   | 発生状況、原因候補、暫定対策、恒久対策  |
| 品質報告書     | 不良内容、影響範囲、原因、再発防止策   |
| 教育資料      | 新人向け工程説明、注意点、よくあるミス  |
| FAQ       | よくある質問と回答            |

ただし、AI生成物は必ず **DraftArtifact** として作られます。

```text
AI生成物 = draft
自動で approved にはならない
人間レビューが必要
```

レビュー導線も持ちます。

```text
draft
↓
in_review
↓
approved / rejected / archived
```

つまり、AIが勝手に正式作業指示や品質判断を確定しない仕組みになります。

# 8. レビュー・承認ワークフロー

ドラフトには reviewer を割り当てられます。

たとえば、

```text
AIが月次点検チェックリストを作成
↓
設備保全リーダーにレビュー依頼
↓
レビューコメントを入力
↓
approved または rejected
↓
履歴を監査ログに残す
```

DraftArtifact には以下が残ります。

```text
created_by
reviewer_id
reviewer_group
assigned_at
reviewed_at
review_comment
approval_decision
source_citations
source_document_ids
template_id
audit_log_ref
```

これにより、AI生成物を安全に業務に乗せられます。

# 9. 管理ダッシュボード

管理者や現場責任者は、ナレッジの状態を見られます。

| ダッシュボード項目          | 意味                 |
| ------------------ | ------------------ |
| 未回答質問              | 文書不足・ナレッジ不足が分かる    |
| 低評価回答              | 改善すべき回答が分かる        |
| 頻出質問               | 現場で困っているテーマが分かる    |
| よく参照される文書          | 重要文書が分かる           |
| obsolete候補         | 古い文書や更新が必要な文書が分かる  |
| ナレッジ不足領域           | 文書化されていない現場知識が分かる  |
| high-risk query数   | 危険・品質系の問い合わせ傾向が分かる |
| safety gate block数 | AIが断定を止めた件数が分かる    |

これは継続課金にかなり効く部分です。
単に「AIで検索できます」ではなく、

```text
現場ナレッジの穴を見つけて改善できます
```

と言えるようになります。

# 10. PoC KPIを測れる

営業やPoCで重要な、効果測定の指標を持てます。

| KPI                             | 何を見るか              |
| ------------------------------- | ------------------ |
| self_resolution_rate            | ユーザーが自己解決できた割合     |
| average_time_to_answer          | 回答までの時間            |
| expert_interruption_reduction   | ベテラン・品質部門への問い合わせ削減 |
| grounded_answer_rate            | 根拠付き回答率            |
| insufficient_evidence_rate      | 根拠不足で答えなかった割合      |
| low_rating_rate                 | 低評価回答率             |
| unanswered_question_count       | 未回答質問数             |
| frequently_referenced_documents | よく使われる文書           |
| obsolete_document_candidates    | 更新が必要そうな文書         |
| knowledge_gap_topics            | ナレッジ不足テーマ          |
| draft_review_completion_rate    | ドラフトレビュー完了率        |
| safety_gate_block_count         | 安全ゲートで止めた件数        |

これにより、PoCでこう説明できます。

```text
導入前は回答に平均15分かかっていたが、導入後は3分に短縮。

```

# 11. 権限管理

部署、工場、役職、設備領域ごとにアクセス制御できます。

たとえば、

```text
第1工場の保全担当は、第1工場設備の保全資料を見られる
品質保証部は品質報告を見られる
営業部は製造原価に関わる文書を見られない
```

基盤側ではすでに、

```text
tenant分離
ACL
deny-by-default
pre-filter
cross-tenant拒否
```

があるので、002ではこれを製造業の部署・工場・役職にマッピングします。

重要なのは、権限のない文書は、

```text
検索結果
回答文脈
引用
ダッシュボード
ドラフト生成
```

のどこにも混ざらないことです。

```text
Excel/Word/PDF内容
メタデータ

回答
引用

フィードバック
```


これは営業資料で大きく使えます。

```text
お客様のデータは、標準ではAIモデルの学習に利用しません。
```

# MVPとして最初に見せられる形

全部を作り切る前でも、最初のPoCではこれが見せられます。

```text
1. PDF / DOCX / XLSX / CSV をアップロード
2. 設備名・アラームコード・不良種別などを付与
3. 現場質問に根拠付き回答
4. 根拠不足なら答えない
5. approved / obsolete / draft の違いを反映
6. high-risk 質問では承認済み文書必須
7. Excelのセル範囲やPDFページを引用
8. 点検チェックリストや報告書を draft 生成
9. reviewer が承認・却下
10. 管理者が未回答・低評価・頻出質問・KPIを見る
```

ここまでできれば、かなり「売れるデモ」になります。

# まとめ

完成するシステムは、単なるRAGではなく、以下を持った製造業向けSaaSです。

```text
製造現場の文書・台帳・過去事例を取り込み、
設備保全・品質不良・作業手順・教育に関する質問へ、
根拠付きで安全に回答する。

危険作業や品質判断では承認済み文書を必須にし、
根拠がなければ答えない。

報告書、点検チェックリスト、教育資料をドラフト生成し、
人間レビューを通して業務に使える。

管理者は未回答、低評価、頻出質問、古い文書、KPIを見て、
現場ナレッジを継続的に改善できる。

顧客データは標準で学習に使わず、
監査ログとガバナンス説明を備えたBtoB向けRAG製品。
```

かなり良いところまで設計が育っています。
ここまで来ると、もう「RAGを作る」ではなく、**製造業のナレッジ運用プロダクトを作る**段階です。
