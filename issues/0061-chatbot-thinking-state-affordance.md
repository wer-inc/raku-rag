# 0061 — チャットボット応答待ちの思考中演出が弱い(系統 = ux / chatbot)

> Priority: **P2/Medium** / Status: In progress / Labels: `ux`, `chatbot`

## 背景(なぜ今)

stg の `/chatbot` 画面確認中に、ユーザーから「chatbot としての演出」「少し考えてるみたいな演出」が必要ではないかという指摘があった。

## どんな課題か

- 回答生成中の表示が小さな進行表示だけで、チャットボットが質問を受け取って処理している感覚が弱い。
- 待ち時間があると、ユーザーは送信できたのか、根拠を確認しているのかを判断しづらい。
- 演出が過剰だと業務ツールとしての信頼感を落とすため、控えめで状態が伝わる表現が必要。

## どこで起きたか

- 画面: `/chatbot`
- API: なし
- コード: `apps/web/app/components/FullSaasScreen.tsx`, `apps/web/app/globals.css`
- 環境: stg ALB URL
- run id / ingestion id / correlation id: なし
- 再現条件: チャットボットで質問を送信し、回答待ち状態になる

## 影響

- 営業デモで「チャットボットらしさ」が弱く、プロダクトの体験品質が低く見える。
- 回答待ち中の不安が増え、二重送信や離脱につながる可能性がある。
- セキュリティ、監査、データ品質への直接影響はない。

## どう解決すべきか

1. 既存の `progress` 状態を使い、回答待ち中に bot の吹き出しを表示する。
2. 「返答準備中」「根拠確認中」「時間がかかっている」の段階を短い文言で伝える。
3. アニメーションは小さなタイピングドットに限定し、`transform` と `opacity` のみで実装する。
4. `prefers-reduced-motion` ではアニメーションを停止する。

## QA checklist

- [ ] 再現テストがある。
- [ ] 正常系が確認できる。
- [ ] 失敗時の表示/応答が確認できる。
- [ ] tenant/ACL 境界を越えない。
- [ ] security/safety gate を弱めていない。
- [ ] Playwright または API smoke で確認できる。
- [ ] AWS stg/live smoke が必要な場合は correlation id を保存する。

## 受け入れ条件(DoD)

- 質問送信後、回答が返るまで bot の思考中吹き出しが表示される。
- 回答待ちが長い場合、人間相談への導線が維持される。
- アニメーションが小さく、業務UIの可読性を邪魔しない。
- 既存の安全ルール、ACL、監査要件を弱めていない。

## スコープ外

- Streaming/WebSocket の導入。
- 回答内容の品質改善。
- セッション管理、RAG、ACL、tenant 分離の変更。
