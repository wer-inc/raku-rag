# 0062 — サイドバー主導線のメニュー過多(系統 = ux / navigation)

> Priority: **P2/Medium** / Status: In progress / Labels: `ux`, `navigation`

## 背景(なぜ今)

営業デモ向けに `/chatbot`、`/sources/*`、`/files` を磨く中で、サイドバーに「質問する」「チャットボット」「ドキュメント」「事例検索」「取込ラン」など近い用途の項目が並び、エンドユーザーが主導線を判断しづらいことが分かった。

## どんな課題か

- メニュー項目が多く、初見ユーザーにとって何を押せばよいか分かりにくい。
- `ドキュメント` は `ファイル` と、`事例検索` は `チャットボット` と、`取込ラン` は `外部接続` の詳細導線と役割が重なって見える。
- 管理・監査・デバッグ用の画面が主導線に出ることで、業務ユーザー向けの体験が重く見える。

## どこで起きたか

- 画面: workspace sidebar
- API: なし
- コード: `apps/web/lib/full-saas.ts`
- 環境: web UI
- run id / ingestion id / correlation id: なし
- 再現条件: ログイン後にサイドバーを見る

## 影響

- 営業デモで「どこを使うサービスか」が伝わりにくい。
- エンドユーザーが管理・調査画面に迷い込みやすい。
- セキュリティ境界への直接影響はないが、運用画面の露出が多いと認知負荷が上がる。

## どう解決すべきか

1. 主導線は `チャットボット`、`外部接続`、`ファイル` に絞る。
2. `/documents`、`/answers/history`、`/sources`、`/ingestion-runs` は画面と直リンクを残し、メニューから非表示にする。
3. citation、ファイル詳細、ソース詳細、運用画面から必要な場合だけ遷移できるようにする。
4. RBAC と tenant/ACL の許可は表示整理とは分離し、直リンク・内部導線を壊さない。

- [ ] 正常系が確認できる。
- [ ] 失敗時の表示/応答が確認できる。
- [ ] tenant/ACL 境界を越えない。
- [ ] security/safety gate を弱めていない。
- [ ] Playwright または API smoke で確認できる。
- [ ] AWS stg/live smoke が必要な場合は correlation id を保存する。

## 受け入れ条件(DoD)

- サイドバーの `回答` グループは `チャットボット` のみになる。
- サイドバーの `データ` グループは `外部接続` と `ファイル` のみになる。
- 非表示にした画面は route と内部リンクから引き続き利用できる。
- 既存の安全ルール、ACL、監査要件を弱めていない。

## スコープ外

- 画面自体の削除。
- API 削除。
- RBAC 変更。
- 監査・承認・RAG 安全ルールの変更。

## 参照

- ユーザー判断: メニューを薄くし、`/documents` と同様の主導線外メニューを非表示にする。
