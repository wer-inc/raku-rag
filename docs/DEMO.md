# 製造ナレッジ RAG — PoC セールスデモ手順書

東洋精機 第一工場を想定した、製造現場向け「根拠付き・安全配慮型」ナレッジ RAG の PoC デモ。
**売りどころは回答精度そのものより、現場で安心して使える“ガバナンス”**：承認済みソースだけを根拠に、
危険作業はブロック／警告し、すべて監査・権限管理される点です。

## 0. 起動（ワンコマンド）
```bash
bash scripts/demo/demo_up.sh      # PG → answer-service(リセット+シード) → API → web
# → http://localhost:3002/
```
ログイン画面 →（任意のメール/PWで）ログイン → 組織選択（東洋精機 第一工場）→ ホーム。

デモ用ナレッジは `scripts/demo/demo_docs.json`（18 文書：保全/品質/安全/事例、承認済み15・旧版1・ドラフト1・承認待ち1）。

> 注: オフラインPoCは決定論的（ハッシュ）埋め込みのため検索は語彙一致ベース。**本番はセマンティック埋め込み**で
> 任意の言い回しに対応します。デモは下記の検証済みクエリで行うと安定します。

---

## 1. 中核：質問 → 根拠付き回答（差別化の本丸）
「質問する」で順に投げる（コピペ可）。各回答に **承認バッジ・有効期限・引用ソース・確信度** が付きます。

| # | デモ質問 | 期待挙動 | 見せどころ |
|---|---|---|---|
| A | `コンベア E-152 点検間隔 M8 ボルト 締付トルク 25` | **回答済み（正常）**・承認済み引用 | 承認済みソースだけを根拠に即答 |
| B | `圧力容器 V-205 耐圧試験 試験圧力 保持時間 昇圧` | **回答済み＋「高リスク」警告**・承認済み引用 | 危険作業は警告＋現場確認を促す |
| C | `受電盤 MCC-3 420V 感電 LOTO ロックアウト 検電` | **回答済み＋「高リスク」**・承認済み引用 | 感電作業も承認手順を根拠に提示 |
| D | `非常停止 ESD-B-Line 解除 リセット 安全リレー` | **回答を保留（ブロック）** | ★レビュー中文書は確定回答しない＝事故防止の目玉 |

- **引用ビューア**：回答の「引用を開く」→ 文書ID/チャンク/承認状態/有効期限/根拠範囲、
  「👍 正しい / 👎 間違い」フィードバック（`/v1/feedback` に記録）。
- 回答下の **👍有用 / 👎要改善** → 改善理由を選ぶと「ナレッジ改善キュー」に入る（後述7）。
- 「回答履歴」に質問・状態・安全・引用数・日時が残る。

> D（ブロック）が最大の刺さりどころ。「**承認済みの根拠が無ければ断定しない**」という安全姿勢を実演。

## 2. ナレッジを入れる：アップロード → 取込
「ソースを追加」→ ファイル（.txt/.md/.csv/Word/Excel）を選択 or テキスト貼り付け →
**承認状態**（承認待ち/承認済み）・発効日を指定 → 「アップロードして取込」。
取込ラン・チャンク数が表示され、「ドキュメント一覧」「取込ラン」に出現。

## 3. 文書承認キュー（承認した文書だけが正式根拠）
「文書承認」→ 取込んだ文書を **承認 / 旧版化**（前進のみのワークフロー）。
承認待ちで入れた文書を **承認** → その場で質問の正式な根拠になる、を実演。

## 4. AIドラフト → レビュー → 承認（検索AIから業務AIへ）
「レビューキュー」→「AIドラフトを作成」（種別=点検チェックリスト、根拠ドキュメントID）→ 生成。
詳細で **担当割当 → 承認/却下**。**承認まで正式利用不可・自動承認は禁止**（終了状態でボタン無効化）。

## 5. 承認状態の制御（approved / draft / obsolete）
回答の引用には承認バッジが付与：**承認済み（緑）/ ドラフト / 旧版**。
「ドキュメント」一覧でも各文書の承認状態が一目で分かる（旧版 `rp-03-reva`、承認待ち `wi-0701-esd-bline` など）。

---

## 6. 運用・コンプライアンス（導入決裁者向け）
- **運用ダッシュボード / 安全テレメトリ / 品質KPI**：質問数・高リスク件数・安全ブロック数・自己解決率（ライブ）。
- **監査ログ**：actor/action/リソース/決定/ハッシュの一覧＋ **CSV出力**（改ざん不可・追記のみ）。
- **ナレッジ改善キュー**：低評価フィードバックを理由別に集約→「文書を追加 / 品質KPI」へ導線→対応済み化。

## 7. 権限漏洩防止（ACL）— 権限シミュレーター
「ロール・権限」→ 権限シミュレーターで同じ質問を別ユーザーで実行：
- **alice（manuals 付与）** → 引用あり（アクセス可）
- **bob（権限なし）** → **0件・「権限により非表示」**（検索結果・引用・回答に一切出ない）

→ 「権限外の文書はそもそも出ない（deny-by-default・サーバ側強制）」を即証明。

## 8. データガバナンス（セキュリティ審査・no-train）
「プロバイダ」→ **顧客データを学習に使わない / 提供元 no-train 必須 / データ所在地（single_region）/
保持期間** を読みやすく提示。BtoB のセキュリティ審査でそのまま使える。

## 9.（参考）検索診断 / 過去トラブル事例
- 「検索設定 → 検索診断」：質問の検索候補・スコア・採用/除外理由・安全判定（「なぜ答えられなかったか」）。
- 過去トラブル事例（`tc-0231` ヒケ・ボイド等）は本番のセマンティック検索で症状起点の事例横断が映えます。

### デモの締めトーク
「**精度だけでなく、現場が安心して使える仕組み**＝承認済みソースだけを根拠に、危険作業はブロック／警告し、
誰が何を見られるか（ACL）・誰がいつ承認したか（監査）・顧客データを学習に使わない（no-train）まで
作り込んである。PoC のこの土台の上に、御社の実文書とセマンティック検索を載せれば、そのまま本番に伸びます。」
