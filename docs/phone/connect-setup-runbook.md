# Amazon Connect セットアップ runbook(024-phone-live-telephony)

実電話で AI オペレータに着信させるための **人間側の手配手順**。コード側(アダプタ Lambda /
Contact Flow / Lex bot / CDK)は 024 ブランチで並行実装する。**最長リードタイムは日本番号の
審査(サポートケース+書類)なので、Step 2 を最優先で開始する。**

## 0. 前提と決定事項

- **法人利用のみ**(personal use では番号申請が却下される — 公式明記)。wer-inc の法人情報で申請する。
- リージョン: **ap-northeast-1(東京)**、既存 stg アカウント(902353451555)に作る。新ステージ/新アカウントは作らない。
- 録音はデフォルト **OFF**(022 の transcript-first 方針)。開示プロンプトは flow 側で制御。
- 番号タイプの推奨: **まず 050 DID**(日額 $0.10・着信 $0.003/分 — 0120/0800 は日額 $0.48・着信 $0.08/分 と桁違いに高い)。0120/0800 は商用提供が決まってからで良い。

## 1. Connect インスタンス作成(コンソール・約10分・番号なしなら追加費用ほぼゼロ)

AWS コンソール → **Amazon Connect**(東京リージオンを確認)→ インスタンスを追加:

1. **ID管理**: 「Amazon Connect にユーザーを保存」(Connect管理ユーザー)
2. **エイリアス**: `raku-rag-stg`
3. **管理者**: 自分用の管理者ユーザーを作成(オペレータ着信テストにも使う)
4. **テレフォニー**: 着信 ✅ / 発信 ✅(発信はテスト用。使わなければ費用なし)
5. **データストレージ**: デフォルトのまま(**通話録音は有効化しない**)
6. 作成後、**インスタンス ARN を控えて私に共有**(CDK/flow 紐付けに使用)
7. インスタンス → 分析とオプティマイズ → **Contact flow logs を有効化**(CloudWatch)

> この時点で「緊急時アクセス」用のログインURL(`https://raku-rag-stg.my.connect.aws/`)が発行される。

## 2. 日本番号の申請(サポートケース) — ★今日開始する

東京リージョンの日本番号(**050 / 03 / 06 DID、0120 / 0800**)は、コンソールから直接取得できず
**AWS サポートケース + 書類3点** が必要(公式)。

**準備する書類(3点必須)**:
1. **所在地証明**(番号の市外局番と一致する住所): 登記簿謄本 / 納税書類 / 公共料金領収書 / 銀行取引明細 のいずれか(**6ヶ月以内**)
2. **代表者の政府発行 ID**: 運転免許証 / パスポート等
3. **代表者と法人の関係証明**: 社員証・在籍証明等(代表者本人なら登記簿で兼ねられるかケース内で確認)

**ケースの起票**:
- サポートセンター → Create case → **Account and billing** ではなく **Technical / Connect (Contact Center)** → Category: Phone number requests
- 記載: インスタンス ARN、希望番号タイプ(**050 DID ×1**)、用途(自社ナレッジ問い合わせ窓口の PoC)、上記書類を添付
- デフォルトクォータは 5 番号まで(今回は1本で十分)

**所要**: 数営業日〜(審査状況による)。**このケース起票だけ先に済ませれば、残りは全部並行できる。**

## 3. 番号待ちの間に起きること(私のタスク・確認不要)

- アダプタ Lambda(VPC内 → answer-service 内部ALB直結、`X-Internal-Auth`)
- DID→テナント解決(SSM パラメータ `raku-rag/stg/phone/did-map`)
- Contact Flow JSON + Lex V2 ja-JP 最小 bot(`infra/connect/` にコミット、コンソール取込手順付き)
- CDK: `phoneTelephony=connect` フラグ(デフォルト OFF — 通常デプロイに影響なし)
- 音声向け回答整形(短文化)+ ブラウザ音声デモ

## 4. 番号が来たら(合流手順・約30分)

1. `phoneTelephony=connect` + インスタンス ARN を CDK context に設定してデプロイ(Lambda 等が乗る)
2. Connect コンソールで Lex bot / Contact Flow を取込み(手順は `infra/connect/README.md`)
3. **電話番号 → Contact Flow を紐付け**
4. 自分の携帯から 050 番号へ発信 → AI 応答 → 「人につないで」→ Connect キュー →
   **CCP(オペレータ画面)で自分が受ける**(Step 1 の管理者ユーザーでログイン)
5. 通話ログが `/phone` 画面の履歴・転送キューに載ることを確認

## 5. セーフティ境界(変更しない)

- 高リスク・根拠不足は断定せず転送(既存の安全ゲートがそのまま効く)
- 録音 OFF / transcript-first、PII 赤入れ済みトランスクリプトのみ保存
- 解約・返金の確約等の業務実行は電話ではやらない(転送のみ)
