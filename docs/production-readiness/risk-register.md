# Production-Readiness Risk Register

**Date:** 2026-06-21 · Companion to the root [`risk-register.md`](../../risk-register.md) (R-001…R-020, *design-intent* risks).
This file adds **production-boundary risks (PR-xxx)** surfaced by the 2026-06-21 A–I audit: risks that exist *because a tested control is not actually deployed / durable / measured*. Where a root risk is mitigated **only at the in-memory core layer**, that is captured here as a deployment-boundary risk.

Severity: Critical / High / Medium / Low. Status: Open / Mitigating / Closed. **[!safety]** = on the always-human safety boundary (`docs/loop-engineering.md §6`).

## Policy
Per the root register: **Critical risks must have an automated hard-gate test before the work is releasable.** For PR-xxx this specifically means the control must be (a) **on the deployed path** and (b) **measured by a real probe/metric**, not only present in the in-memory core. Production-readiness is reached when every Critical/High PR is Closed (control deployed + durable + measured) and the eval gate computes real security/quality probes over a representative corpus.
